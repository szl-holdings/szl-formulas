# Changelog

## Unreleased

- The package quickstart docstring (`torch-ext/szl_formulas/__init__.py` and its build mirror) loaded the Kernel Hub copy with `revision="main"` and `trust_remote_code=True`, contradicting the README rule that only a verified immutable 40-hex Kernel Hub revision may be loaded. It now reads the revision from `SZL_FORMULAS_HF_REVISION`, rejects anything that is not 40 lowercase hex characters, and no longer labels a Hub load as offline. Documentation only: no code path, formula, proof status or locked count changes. `tests/test_kernel_load_guidance.py` checks both package copies and the README. The published Hub copy keeps the old docstring until the owner republishes.
- The governed composer applies the 2026-10-11 PAC-Bayes score policy to every `RISK_LIKE` formula (`hoeffding_tail`, `pinsker_kl_bound`, `fisher_rao_distance`, `bekenstein_cascade`): a finite nonnegative output `v` maps to `max(0, 1 - v)`, so a vacuous value (`v >= 1`) scores zero and a larger risk can no longer raise the score. Before, `v > 1` mapped to `v / (1 + v)` (2.0 -> 0.667, 1e17 -> 1.0), so as a single step a value just above 0.5 halted on `axis_floor` while any value above 1 passed; `+inf`, `-inf`, NaN, negative, `False` and empty-list outputs scored 1.0 with every validator passing, and `STRUCTURAL` steps scored 1.0 for every output. `bekenstein_cascade(inf, 1.0)`, `bekenstein_cascade(nan, 1.0)`, an overflowing `pinsker_kl_bound`, `reed_solomon_singleton(inf, 1.0)` and `reed_solomon_singleton(Decimal("Infinity"), 1)` reached this with inputs the formulas accept. A `RISK_LIKE` output must now be an `int` or `float`; a float subclass such as `numpy.float64` is read as its plain value, so the receipt scalar is always a builtin float. Negative, nonfinite, boolean or nonnumeric outputs, and other numeric types (`Fraction`, `Decimal`, `numpy.float32`, numpy integers, mpmath or torch scalars, which used to score 0.5 whatever their value), raise inside the governed exception boundary and halt before adding a receipt. A `STRUCTURAL` output that is a nonfinite number of any numeric type (float, complex, `Decimal`, a numpy, mpmath or torch scalar, or any value with `__float__`, `__complex__` or `__index__`) raises the same way, as does one whose numeric conversion fails. Integers, `Fraction` and `Decimal` are checked without converting to float, so a finite value above float range still scores 1.0, and a non-numeric output such as a dict keeps 1.0. Formula code and outputs, the generic scalar mapping for other formulas, hash format, proof status and domain checks are unchanged. Migration: a governed loop that continued after a `RISK_LIKE` output `>= 1` now halts on `axis_floor` with a zero-score receipt. That includes every `bekenstein_cascade` result with `R * E` at or above about 5.03e-27 (SI units, so any macroscopic system), and `pinsker_kl_bound` or `fisher_rao_distance` of far-apart distributions, whose ranges are [0, 2] and [0, pi]. A loop whose `RISK_LIKE` step returns any number other than an `int` or `float`, or whose `STRUCTURAL` step returns a nonfinite number, now halts with `step i (<name>) raised: ...` and no receipt for that step. A domain-normalised score (for example `pinsker_kl_bound / 2`, `fisher_rao_distance / pi`) is not adopted here and remains an owner decision. `tests/test_composer_risk_scores.py` tests both package copies. `tests/test_lambda_v1_conformance.py::test_governed_loop_never_feeds_lambda_an_out_of_domain_scalar` now starts from an in-range `bekenstein_cascade` step, so its NaN step still runs, and asserts that it does. One `tests/test_pac_bayes_domain.py` assertion that pinned the old `2.0 -> 2/3` mapping now expects `0.0`. The build mirror is regenerated with the normal sync script.

## 2026-10-11

- The governed composer now maps a finite nonnegative PAC-Bayes bound `b` to `max(0, 1 - b)`. The formula still returns its untruncated bound, and accepted formula inputs keep their existing numerical results. A vacuous bound (`b >= 1`) has advisory score zero; increasing the bound can no longer improve that score. This preserves the existing axis-floor policy: a failed validator retains its diagnostic receipt but seals the root and aggregate at the last accepted step. Negative, nonfinite, boolean or nonnumeric PAC-Bayes outputs halt before adding a receipt. Scalar-conversion exceptions now use the same governed halt boundary as formula exceptions; `KeyboardInterrupt` and `SystemExit` still propagate. Other formulas' scalar mappings, hash format, proof status and domain checks are unchanged. Migration: callers that previously continued after a vacuous PAC-Bayes result must now handle an axis-floor halt. Both complete package copies are tested independently; the build mirror is regenerated with the normal sync script. This source change does not qualify or publish a Hub runtime, and the draft's domain and canonical-source coordination decisions remain with the owner.

## 2026-10-07

- `pac_bayes_mcallester` fails closed on out-of-domain input (frontier-v3 PR B; brief MAT-F08 and the PAC-Bayes applicability addendum; recon R05-F08). Every argument must be a real, finite number (bool rejected); `0 <= empirical_risk <= 1`; `kl >= 0`; `n` an `int >= 8` (Maurer 2004 validity; `n >= 1` is the recorded alternative, owner decision); `0 < delta < 1`; a `kl` or `n` beyond float range raises `ValueError` instead of leaking `OverflowError`. The NaN-swallowing `max(0.0, complexity)` clamp is gone: for every valid input `ln(2*sqrt(n)/delta) > ln 2`, so the complexity term is strictly positive. The float expression is unchanged, so every input the new domain accepts evaluates to the same float as before (baseline `(0.1, 1.0, 1000, 0.05) -> 0.1638073549585195`); only the domain moved. Docstring attribution corrected to "Maurer (2004) refinement of McAllester (1999)". `PROOF_STATUS` stays `SORRY(PACBayes)` verbatim; REGISTRY, atlas payload and the locked-proven count (8) are untouched. `build/torch-universal` regenerated by `scripts/sync_source_mirrors.py`. New `tests/test_pac_bayes_domain.py` exercises both package copies and the governed loop (a raised step now halts with no receipt). Migration: callers passing `n` as a float (e.g. `1000.0`) or `n < 8` must pass an `int n >= 8`; a raised `ValueError` now halts the governed loop with no receipt.
